Setup

Each run is one process (examples/experiment.rs --workload packages) simulating the whole network on the in-process fake wire, with the fake DNS resolver and its five test domains as publishers. Packages are published with registry::publish_package and installed with registry::install_package, the same functions the CLI's publish and install commands call. Package i belongs to test domain i mod 5 and is published from one random node, version 1.0.0, 2.0.0, … in order; each version's blob is random bytes. Installs run from random nodes; half ask for the latest version, half for a random published one. An install counts as correct only if it returned the version asked for (for "latest", the newest that was published) with exactly the bytes published for it.

Each configuration is repeated with several seeds; plots show the mean over seeds with a band of ±1 standard deviation, and tables give mean ± std and the variance.

Install and publish cost vs network size

20 packages × 5 versions published on a clean wire, then 500 installs from random nodes (half the latest version, half a random published one). An install fetches the latest pointer (asking all K closest nodes, so a stale replica cannot hide a newer version), walks every version record back to the first, verifying each signature and hash, and then fetches the package blob.

  • Each doubling of N adds about 4.9 RPCs to an install: the logarithmic growth of every lookup inside it, times the number of lookups an install makes.

Cost vs length of the version chain

10 packages with 1–64 versions each, on 1000 nodes. Installing any version walks the chain from the latest pointer back to the first version, one lookup per record, so the cost should grow linearly with the number of versions. Publishing version j first loads the j − 1 records before it, so publishing a whole history of V versions costs O(V²).

What the numbers mean

  • An install makes 1.00 lookups per version in the chain plus 2.0 fixed (latest pointer and blob): linear, as the chain walk predicts.

Install reliability vs packet loss

Packages published on a clean wire, then installed with each datagram dropped with probability p. An install chains V + 2 = 7 lookups (pointer, 5 records, blob) and fails if any of them does, so if a single value lookup succeeds with probability s(p), an install should succeed with about s(p)^7.

What the numbers mean
